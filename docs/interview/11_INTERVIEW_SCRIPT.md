# 11 · 口述稿（30 秒 / 1 分钟 / 3 分钟 / 8~10 分钟）

> 工程师口吻，去"我感觉/大概"这类词，全部换成可被追问的实点。括号内是可在白板上随手画的东西。

## 一、30 秒（电梯陈述）

> "这是我实习做的**维特智能 ESP32-S3 双路串口 WiFi 数据记录仪**——面向客户定制的产品。它把两路 UART 的原始数据实时落 SD 卡，手机连热点打开网页就能看实时数据、控制启停、下载文件，插上 USB 线它就是一个 U 盘加虚拟串口的复合设备。技术栈是 ESP-IDF + C + FreeRTOS。**我负责数据链路侧——双路 UART 接入、双向路由、SD 落盘、文件管理 API、参数持久化**，Web 实时监控由同事负责。"

## 二、1 分钟（加"怎么做的"）

> 接 30 秒版本后补一段："实现上分四块：**采集**——两路 UART，CH1 用 UART0、CH2 用 UART2，各自一个 FreeRTOS 收数任务；**存储**——每路 16KB 环形缓冲，攒到 2KB 或超时 1 秒就批量写 SD，再每秒 fsync 兜底防掉电；**联网**——WiFi 走 AP+STA 混合，AP 永远在线供手机管理，STA 可连外网、掉线自动重连三次；**USB**——TinyUSB 做 CDC 虚拟串口加 MSC 读卡器的复合设备，难点是同一张 SD 卡在本地记录和 U 盘模式之间切换所有权，我做了 mount/unmount 回调来互斥。"
>
> 结尾留钩子："整个项目是 v1.1 到 v1.3 的迭代，如果时间够我可以按版本讲演进。"

## 三、3 分钟（架构主线）

1. **定位**（10s）：串口黑匣子，接两台设备之间透明记录。
2. **数据流主线**（60s）："一条数据进来怎么走？" → UART RX task → `recorder_write_rx_channel` 一分为二：一路进 256 条 live 环形缓冲给 Web 200ms 轮询看，一路进 16KB save_rb 由 rec_io 任务按双条件落盘 SD，rec_sync 每秒 fsync。同一条数据还进 router 双向转发到另一个串口。（边讲边画 `02_SYSTEM_ARCHITECTURE.md` 的 mermaid）
3. **并发模型**（50s）：5 个 FreeRTOS 任务 + 互斥量/信号量/事件组/portMUX，讲优先级设计和背压（SD 慢怎么不丢？缓冲 + 独立任务 + drop 统计）。
4. **外设**（40s）：SD 走 SPI 不用 SDMMC（省引脚）；USB 复合设备枚举；WiFi AP+STA。
5. **诚实边界**（20s）：编译通过 + **部分实机验证通过**（8.4 记录：SD 挂载/WiFi AP/Web/落盘+fsync/USB 热插拔 ✓），双路串口端到端当时仍在收尾；v1.3 源码不在本次仓库。

## 四、8~10 分钟（版本演进主线——最出彩）

### 开场（30s）
"我这个项目最大的价值不在某个单点功能，而在于**一个可以讲清楚的版本演进**：从 v1.1 的'能跑'，到 v1.2 的'能扛'，再到 v1.2_dev/v1.3 的'能测、能交付'。我按版本讲。"

### v1.1 —— 双 UART 接入 + 全功能打通（2 分钟）
- 目标：`docs/ESP32.md` 的需求——双路串口、SD 记录、网页、U 盘。
- 分工（7.27 定）：**我负责双路 UART 接入、数据路由、SD 落盘、文件管理 API、参数持久化；同事蔡茹锦负责 Web 实时监控。**
- 落地：双路 UART（CH1=UART0/43/44，CH2=UART2/17/18）、`data_router` 双向透传、`data_recorder` 环形缓冲落盘、`web_server` 14 个 API、TinyUSB CDC+MSC。
- **7.28 我修了三个真实 bug**：尾部缓存未落盘、Web 输入 ID 冲突、USB CDC/MSC 描述符冲突（代码对照见 `08_DEBUG_AND_PROBLEMS.md` 问题 0）。
- 一句话：**v1.1 把"需求清单"变成了"编译通过 + 部分实机验证"的 16 项功能。**

### 接手审计 + 实机验证（1 分钟，讲反思，很加分）
- 7.27 有一份 `HANDOVER_AUDIT_STAGE1.md`（接手审计），它没有烧板、只靠读代码和 `idf.py build`，就定位了 7 个问题：UART0 与控制台冲突、停止记录丢缓冲、前后端 API 不一致、分区 2MB/16MB 矛盾、事件回调里 sleep 5 秒等。
- 我学到的是**证据分级**：代码存在 ≠ 编译通过 ≠ 硬件验证。
- **实机结果（作者自述）**：7.29 烧录成功（热点可访问）；7.30 双通道接入验证通过 + CH2→CH1 路由 1 字节丢包 0；8.4 实机验证通过 SD 挂载 / WiFi AP / Web / 落盘+fsync / USB 热插拔，双路串口端到端当时仍在收尾。

### v1.2 —— 加固 + 补全（3 分钟，讲 4 个具体 diff）
1. **容错降级**：SD/USB/recorder/WiFi 初始化失败从 `ESP_ERROR_CHECK` 硬 abort 改成记日志继续跑——"没插 SD 也能用 WiFi/Web"。证据：`app_main.c` L92-L117。
2. **补 API**：从 14 个路由补到 22 个，把前端调用的 `/api/wifi/scan`、`/api/config/uart` 等补上，解决"假闭环"。证据：`web_server.c` L776-L797。
3. **完整 UART 参数**：新增 `user_uart_configure_channel()`，波特率/数据位/停止位/校验位都能运行时改，解决 v1.1 "只支持 8N1"。证据：`uart_driver.c` L163-L201。
4. **配置 NVS 化**：从"只存 SD"改成"NVS 为主 + SD 镜像"，拔卡也能读配置。证据：`config_manager.c` L287-L330。
- 一句话：**v1.2 把"能跑"变成了"能扛"。**

### v1.2_dev / v1.3 —— 桥接、测试、时间同步（1 分钟 + 诚实说明）
- v1.2_dev 加 `usb_cdc_bridge`（USB CDC ↔ UART 桥，解决 v1.1 的 CDC 数据被丢弃）。
- v1.3_release_test 加 **cdc 测试协议 / 时间同步 / 安全测试模式**——面向产测和交付。
- ⚠️ **诚实说明**：这两个版本的源码是嵌套 git 仓库，随归档没有进本次仓库（空 gitlink），所以这几块我只能讲设计目标，不能逐行举证。**面试时一定主动说，不要被追问才发现。**
